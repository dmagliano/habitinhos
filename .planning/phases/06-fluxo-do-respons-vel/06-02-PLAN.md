## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| child form -> Spring API | Responsible JWT and child profile request fields cross into protected child endpoints. |
| inactive child visibility -> mobile UI | History-preserving inactive records become visible in a management context. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-02-01 | Elevation of Privilege | child management service | mitigate | Service never accepts/sends familyUnitId; backend family scoping remains authoritative. |
| T-06-02-02 | Tampering | child form | mitigate | Client validation is UX only; backend validates request; tests lock route/body shape. |
| T-06-02-03 | Repudiation | deactivate child | mitigate | UI copy says deactivate, not delete; backend soft-deactivation response is shown/refetched. |
| T-06-02-04 | Information Disclosure | inactive child list | mitigate | Inactive children appear only in responsible authenticated management screens. |
</threat_model>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mobile responsible service -> Spring API | Responsible JWT crosses into dashboard/list endpoints. |
| backend dashboard aggregation -> database | Multiple family-scoped repositories are combined into one response. |
| route params -> child detail | Child id selected in mobile route drives a detail read. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01-01 | Elevation of Privilege | dashboard/list endpoints | mitigate | Derive family from `CurrentUserProvider`; integration tests create two families and assert cross-family data is absent. |
| T-06-01-02 | Information Disclosure | responsibleService/dashboard UI | mitigate | Never render JWT, familyUnitId, stack traces, or raw backend internals; use ApiError.userMessage or fixed PT-BR copy. |
| T-06-01-03 | Tampering | includeInactive query | mitigate | Query parameter only changes visibility of family-owned records; it never bypasses family scoping. |
| T-06-01-04 | Spoofing | mobile dashboard aggregates | mitigate | Mobile renders backend aggregate values only and does not compute authoritative balances or status counts locally. |
</threat_model>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mission form -> Spring API | Mission template and assignment request fields cross into protected mission endpoints. |
| approval actions -> wallet ledger | Approve/reject requests trigger backend status transitions and possible wallet credits. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03-01 | Tampering | mission create/update | mitigate | Client validates positive coin value, backend remains authoritative, tests lock payload names. |
| T-06-03-02 | Elevation of Privilege | assignment | mitigate | Child ids come from active children endpoint under responsible JWT; no familyUnitId accepted. |
| T-06-03-03 | Repudiation | rejection reason | mitigate | Rejection UI captures optional reason and sends it to backend; success feedback comes after backend response. |
| T-06-03-04 | Spoofing | approval wallet updates | mitigate | UI never credits coins locally; it refetches backend dashboard/wallet state after approval. |
</threat_model>

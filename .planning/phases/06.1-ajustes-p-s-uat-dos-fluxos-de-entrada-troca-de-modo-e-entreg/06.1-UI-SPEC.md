# Phase 06.1 - UI Design Contract

> Contrato visual e de interacao para os ajustes pos-UAT de entrada,
> autenticacao, troca de modo e entrega de resgates no app mobile.

## Escopo

A Phase 06.1 corrige a experiencia testada apos a Phase 6. Ela deve manter o
sistema visual ja aprovado nas fases 5 e 6, sem criar uma nova linguagem
visual. O objetivo e deixar a jornada real de demo mais direta:

- entrada deslogada com boas-vindas, Login e Registro;
- login com opcao explicita `Mantenha-me conectado`;
- entrada autenticada orientada ao modo criança, sem hub obrigatório
  `Sou responsável` / `Sou criança`;
- acesso à gestão familiar pelo modo criança;
- retorno claro do modo responsável para o modo criança;
- dashboard responsavel com links acionaveis para aprovacoes e resgates
  recentes;
- cards de resgate recente com checkbox `Entregue` e data de entrega.

Fora do escopo: seeds de demo, README, roteiro de apresentacao, revisao visual
global da Phase 7, PIN de responsavel e qualquer imagem/asset novo.

## Product Feel

Esta fase deve parecer uma lapidacao do app, nao uma tela nova colada por cima.
O tom da entrada e acolhedor e familiar. O modo crianca continua alegre e
simples. O modo responsavel continua calmo, organizado e confiavel.

Hierarquia obrigatoria:

1. Entrada clara: `Habitinhos`, valor do app, Login e Registro.
2. Autenticacao honesta: campos rotulados, erro amigavel, estado loading e
   opcao de persistencia visivel.
3. Modo crianca como caminho natural da demo.
4. Gestao familiar como acao secundaria mas facil de achar.
5. Dashboard responsavel com atalhos acionaveis e resgates com estado de
   entrega persistente.

## Spacing Scale

Usar `mobile/src/theme/spacing.ts`. Todos os valores sao multiplos de 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gaps entre checkbox/texto, emoji/texto e badges |
| sm | 8px | Gaps compactos, chips e metadados |
| md | 16px | Padding padrao de cards, campos e listas |
| lg | 24px | Espaco entre secoes e header/conteudo |
| xl | 32px | Grupos principais da entrada e formularios |
| xxl | 48px | Separacao maior em boas-vindas com pouco conteudo |
| xxxl | 64px | Respiro excepcional, somente se nao empurrar CTAs abaixo da dobra |

Constantes:

| Token | Value | Usage |
|-------|-------|-------|
| screenHorizontal | 20px | Padding horizontal padrao Android 360px-430px |
| cardPadding | 16px | Padding interno de cards |
| bottomSafePadding | 24px | Respiro acima da safe area e bottom tabs |

Exceptions:

- Alvos de toque usam minimo `44x44`.
- `PrimaryButton` usa `minHeight: 56`.
- `SecondaryButton`, checkbox pressable, chips e opcoes segmentadas usam
  `minHeight: 48`.
- Checkbox visual pode ter `24x24`, mas a area tocavel do row deve ser ao
  menos `44px` de altura.
- Cards de resgate entregue nao mudam dimensao ao marcar `Entregue`.

## Typography

Usar somente fonte do sistema e os tokens atuais.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 24px |
| Label | 14px | 700 | 20px |
| Heading | 20px | 700 | 28px |
| Display | 28px | 700 | 36px |

Regras:

- Texto principal nunca fica abaixo de 16px.
- `Display` fica reservado para brand/headline de entrada e titulos de tela.
- Labels de checkbox e metadados usam `Label` ou `Body`; nao usar texto menor.
- Texto de card entregue usa a mesma tipografia e muda para `textMuted`, sem
  reduzir tamanho ou depender apenas de opacidade.
- Titulos longos de recompensa quebram em ate duas linhas; nao reduzir fonte
  para caber em uma linha.

## Color

Usar `mobile/src/theme/colors.ts` como fonte unica.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F5FBF8` | Fundo do app e safe areas |
| Secondary (30%) | `#FFFFFF`, `#EFF5F3`, `#E9EFED`, `#EAF7FE` | Cards, paineis, inputs, tab bar e estados disabled |
| Accent (10%) | `#4FD1C5` | CTA primaria, tab ativa, selecao, checkbox marcado |
| Coin/reward semantic | `#F6AD55`, `#FFF3DF`, `#8E4E11` | Moedas, custo e recompensa |
| Success semantic | `#38A169`, `#E6F7ED` | Entrega confirmada e feedback positivo |
| Warning semantic | `#F6AD55`, `#FFF3DF` | Aprovações pendentes e atencao |
| Destructive | `#BA1A1A`, `#FFDAD6` | Logout, erros e acoes destrutivas |

Accent reserved for:

- `Entrar`, `Criar conta`, `Confirmar registro`;
- checkbox `Mantenha-me conectado` quando marcado;
- checkbox `Entregue` quando marcado;
- tab ativa e estados selecionados;
- acao positiva de salvar/confirmar.

O laranja de moedas nao e cor generica de acao. Ele fica restrito a
`CoinBadge`, custo de recompensa e comunicacao de saldo/moedas.

Status nunca depende so de cor. Todo status usa texto, forma/badge/checkbox e
quando util um emoji discreto.

## Component Contracts

Reaproveitar componentes existentes antes de criar novos:

| Component | Phase 06.1 Contract |
|-----------|---------------------|
| `AppScreen` | Safe area, fundo, padding horizontal e scroll quando conteudo passa da tela |
| `AppHeader` | Titulos de login/registro, perfil, dashboard e acoes simples |
| `Card` | Formulario de login/registro, entrada, resgate recente e paineis de estado |
| `PrimaryButton` | Acao principal: `Entrar`, `Criar conta`, `Confirmar entrega` quando necessario |
| `SecondaryButton` | `Login`, `Registro`, `Gerenciar família`, `Voltar para o modo criança`, `Cancelar` |
| `StatusBadge` | Sessao, entregue, aguardando aprovacao, erro recuperavel |
| `MetricSummaryCard` | Pode virar pressable para `Resgates recentes`; deve manter dimensoes estaveis |
| `ApprovalCard` | Deve continuar com label acessivel `Abrir aprovacoes` |
| `BottomTabBar` | Mantem tabs de crianca e responsavel sem criar nova nav visual |

Novos componentes permitidos:

| Component | Contract |
|-----------|----------|
| `AuthWelcomeScreen` | Entrada deslogada com brand, headline, supporting copy e duas acoes: `Login` e `Registro` |
| `RegisterScreen` | Formulário com `Nome`, `E-mail`, `Senha`, `Nome da família`, submit e erro amigável |
| `RememberSessionControl` | Checkbox/row pressable com label `Mantenha-me conectado` e estado marcado/desmarcado |
| `DeliveredCheckbox` | Checkbox/row `Entregue`; marcado mostra estado visual success/muted e data persistida |
| `RedemptionSummaryCard` | Card de resgate com título, criança, custo, checkbox, estado entregue e data |

Regras:

- Checkbox deve ser um `Pressable` com `accessibilityRole="checkbox"` e
  `accessibilityState={{ checked }}`.
- Nao usar switch para `Entregue`; checkbox comunica uma tarefa concluida.
- Nao usar checkbox para login/registro como botao solto sem label.
- `Gerenciar família` e `Voltar para o modo criança` devem ser botões com
  texto, nao apenas icones.
- Estado entregue deve deixar texto em `textMuted`, mas manter contraste e
  legibilidade.

## Navigation Contract

Rotas esperadas ou equivalentes:

| Route | Purpose |
|-------|---------|
| `AuthWelcome` | Entrada deslogada com Login e Registro |
| `Login` ou `Auth` em modo login | Formulario de login com lembrar sessao |
| `Register` | Cadastro de responsável/família |
| `ChildProfileSelect` | Primeira entrada autenticada quando não há criança ativa escolhida |
| `ChildTabs` | Modo criança |
| `ResponsibleTabs` | Modo responsável/gestão familiar |
| `ResponsibleApprovals` | Fila de aprovacoes pendentes |
| `ResponsibleHome` | Dashboard com resgates recentes focaveis |

Regras:

- Deslogado: abrir `AuthWelcome` ou tela equivalente, nao o formulario de login
  diretamente.
- `AuthWelcome` deve ter CTA primaria `Login` e acao secundaria `Registro`, ou
  duas acoes de peso equivalente se a composicao visual exigir.
- Após login/registro, a pilha autenticada deve entrar em `ChildProfileSelect`
  ou `ChildTabs`, não no hub obrigatório com `Sou responsável`/`Sou criança`.
- `FamilyHub` pode permanecer como fallback técnico, mas não deve ser a rota
  normal da demo após autenticação.
- No perfil da criança, `Gerenciar família` abre `ResponsibleTabs` preservando
  a criança ativa quando possível.
- No perfil responsável, `Voltar para o modo criança` volta para `ChildTabs`
  quando há criança ativa; se não houver, abre `ChildProfileSelect`.
- O card/box de aprovacoes abre `ResponsibleApprovals`.
- O card/metrica `Resgates recentes` deve rolar/focar a secao de resgates ou
  abrir tela equivalente de resgates recentes. O comportamento precisa ser
  testavel.

## Screen Contracts

### AuthWelcome

Purpose: orientar o usuario deslogado antes de pedir credenciais.

Visual:

- Brand `Habitinhos` no topo do conteudo principal.
- Headline curta: `Transforme tarefas em pequenas conquistas`.
- Supporting copy: `Organize missões, moedas e recompensas da família.`
- Card ou painel de entrada com duas acoes visiveis:
  - `Login`
  - `Registro`
- Badge discreto ou texto curto pode comunicar `Missões, moedas e recompensas
  em família`.

States:

| State | Contract |
|-------|----------|
| Ready | Mostra brand, headline, supporting copy, Login e Registro |
| Restoring | Usar `AuthLoadingScreen`; não mostrar botões enquanto sessão restaura |
| Offline restore error | Mostrar erro amigavel e `Tentar novamente` quando aplicavel |

### Login

Purpose: autenticar responsavel com controle explicito de persistencia.

Fields:

- `E-mail`
- `Senha`
- checkbox `Mantenha-me conectado`

Copy:

| Element | Copy |
|---------|------|
| Title | `Entrar na conta` |
| Supporting | `Acesse a família para continuar as missões.` |
| Primary CTA | `Entrar` |
| Loading CTA | `Entrando...` |
| Secondary action | `Criar conta` or `Voltar` depending on route shape |
| Error | Use `ApiError.userMessage`; fallback `Não conseguimos entrar agora. Tente novamente.` |

Rules:

- Checkbox default: unchecked unless planning explicitly decides otherwise.
- Checked state persists token in SecureStore.
- Unchecked state keeps the runtime session but must not restore after app
  restart.
- Submit duplicate is disabled while loading.

### Register

Purpose: criar responsavel e familia usando `POST /auth/register`.

Fields:

- `Nome`
- `E-mail`
- `Senha`
- `Nome da família`

Copy:

| Element | Copy |
|---------|------|
| Title | `Criar conta` |
| Supporting | `Cadastre a família para começar a organizar missões.` |
| Primary CTA | `Criar conta` |
| Loading CTA | `Criando conta...` |
| Secondary action | `Já tenho conta` |
| Success | Entrar no fluxo autenticado sem tela intermediaria de marketing |
| Error | `E-mail ja cadastrado.` or friendly backend/user message |

Rules:

- Nao adicionar campos fora do backend `RegisterRequest` nesta fase.
- Senha permanece `secureTextEntry`.
- Labels ficam sempre visiveis; placeholders nao substituem labels.

### ChildProfile / Modo Crianca

Purpose: permitir que a crianca continue sua jornada e acesse gestao familiar
quando necessario.

Required changes:

- Trocar copy `Voltar para família` por `Gerenciar família` quando a ação leva
  ao modo responsavel.
- `Trocar criança` permanece disponível.
- `Sair da conta` permanece destrutivo.

Visual:

- Manter `EmojiAvatar`, nome da criança e nome da família.
- Ações em coluna, com `Gerenciar família` como `SecondaryButton` antes de
  `Sair da conta`.
- Não exibir opções `Sou responsável` / `Sou criança` dentro do caminho normal.

### ResponsibleProfile / Modo Responsavel

Purpose: deixar claro que o usuario esta gerenciando a familia e pode voltar
ao modo crianca.

Required copy:

- Texto de apoio: `Você está gerenciando a família.`
- Ação: `Voltar para o modo criança`
- Fallback quando não há criança ativa: `Escolher criança`

Rules:

- `Voltar para o modo criança` não faz logout.
- `Sair da conta` continua separado e destrutivo.
- Não apresentar retorno como `Voltar para família`, porque esse texto remete
  ao hub antigo.

### ResponsibleHome Dashboard Links

Purpose: tornar cards/metrica acionaveis sem alterar a densidade do dashboard.

Required behavior:

- `ApprovalCard` continua abrindo `ResponsibleApprovals`.
- `MetricSummaryCard` de `Resgates recentes` deve ser pressable ou haver CTA
  explicita `Ver resgates recentes`.
- Ao acionar resgates recentes, a secao `Resgates recentes` deve ganhar foco,
  rolar para a secao, ou abrir tela equivalente.

Visual:

- Pressable metric card deve preservar `minHeight: 88`.
- Usar helper curto se necessario: `Ver ultimos resgates`.
- Estado pressionado pode usar `primarySoft` ou `surfaceMuted`, mantendo texto
  legivel.

### Recent Redemption Card

Purpose: mostrar resgates e permitir marcar entrega fisica/real.

Required content:

- Titulo da recompensa.
- Crianca.
- Custo em moedas.
- Checkbox `Entregue`.
- Quando entregue: `Entregue em: {data}`.

State mapping:

| Backend State | Checkbox | Text | Extra Copy |
|---------------|----------|------|------------|
| `REDEEMED` with no `deliveredAt` | unchecked | `textPrimary` / `textSecondary` | none |
| `DELIVERED` or `deliveredAt != null` | checked | `textMuted` for title/meta | `Entregue em: {formattedDate}` |
| mutation loading | disabled | preserve previous state | optional `Salvando...` |
| mutation error | previous checked state | normal/error helper | `Não conseguimos marcar como entregue. Tente novamente.` |

Rules:

- Marcar `Entregue` nao remove o card da lista.
- Marcar `Entregue` nao altera custo, saldo ou moedas.
- A data exibida vem do backend depois do sucesso sempre que possivel.
- Se a API retornar data ISO, exibir em formato PT-BR curto consistente com o
  restante do app, por exemplo `03/06/2026`.

## API Data Contract For UI States

UI must consume real backend data and must not invent local truth for session,
family context, dashboard counts, or delivered redemptions.

| Backend Data | UI Use |
|--------------|--------|
| `POST /auth/login` | Login session |
| `POST /auth/register` | Registro session |
| `GET /me` | Session restore when token was persisted |
| `GET /dashboard/responsible` | Children, approvals, recent redemptions, delivery metadata |
| mark-delivered endpoint chosen by planner | Persist `Entregue` and return delivery metadata |

Delivery response must expose enough data for UI:

- redemption id;
- status or derived delivered boolean;
- `deliveredAt`;
- existing reward title, child name/id and cost in dashboard projection.

No UI state may display `Entregue em` unless the mutation succeeded or the
dashboard response already contains `deliveredAt`.

## Accessibility

- Todos os botoes e checkboxes possuem `accessibilityLabel`.
- Checkbox `Mantenha-me conectado` usa role checkbox e checked state.
- Checkbox `Entregue` usa label com objeto quando possível:
  `Marcar Cinema em família como entregue`.
- `Gerenciar família` e `Voltar para o modo criança` usam texto visível e alvo
  minimo 48px.
- Status entregue combina checkbox, texto e cor; nao depende apenas do cinza.
- Loading e erro de entrega devem ser anunciaveis por texto visivel.

## State Requirements

| Flow | Loading | Empty | Error | Success |
|------|---------|-------|-------|---------|
| Auth welcome | `AuthLoadingScreen` during restore | n/a | retry restore when applicable | navigate to authenticated child flow |
| Login | Disable submit, show `Entrando...` | n/a | friendly inline error | authenticated child flow |
| Register | Disable submit, show `Criando conta...` | n/a | friendly inline error | authenticated child flow |
| Child profile mode switch | n/a | no children state remains in selector | route fallback to selector | responsible tabs |
| Responsible return | n/a | no active child -> selector | no silent failure | child tabs |
| Dashboard links | preserve layout | recent empty state | localized retry | focused/visible section |
| Mark delivered | disable checkbox/card action | n/a | restore prior visual state with helper | checked, muted text, delivered date |

## Verification Expectations

The implementation plan should include tests that prove:

- unauthenticated entry renders Login and Registro before any login-only form;
- login calls auth with `Mantenha-me conectado` checked/unchecked behavior;
- register uses the real mobile auth service and authenticated session shape;
- authenticated normal entry does not show mandatory `Sou responsável` /
  `Sou criança` hub;
- child profile shows `Gerenciar família`;
- responsible profile shows `Voltar para o modo criança` or `Escolher criança`
  fallback;
- approval card opens pending approvals;
- recent-redemptions action focuses/opens recent redemptions;
- `Entregue` mutation persists and renders `Entregue em: {data}`;
- delivered card state remains after dashboard refetch.

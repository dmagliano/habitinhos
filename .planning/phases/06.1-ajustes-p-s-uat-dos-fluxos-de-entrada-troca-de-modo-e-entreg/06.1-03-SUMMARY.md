**Reward redemption delivery is now persisted, projected into the dashboard, and controllable from the responsible mobile UI.**

## Accomplishments

- Added delivered fulfillment state to reward redemptions with Flyway migration, enum value, nullable `deliveredAt`, and an idempotent domain method.
- Added responsible-only `PATCH /reward-redemptions/{id}/delivered`, scoped by the current user's family and returning the updated redemption DTO.
- Covered delivery invariants: cross-family denial, repeated delivery preserves first timestamp, no wallet balance change, and no new coin transaction.
- Extended responsible dashboard recent-redemption DTOs with `status` and `deliveredAt`.
- Added mobile API types, `responsibleService.markRedemptionDelivered`, and an accessible `Entregue` checkbox in recent redemption cards.
- Delivered cards stay in the list, render muted text, and show `Entregue em: {data}` from backend data.

## Decisions Made

- Used `PATCH /reward-redemptions/{id}/delivered` as the stable endpoint because delivery is a partial state transition on an existing redemption.
- Kept `redeemedAt` as the original redemption creation timestamp and added `deliveredAt` as a distinct fulfillment timestamp.
- Kept delivered cards visible in recent redemptions so the responsible can audit what was redeemed and what has already been handed over.

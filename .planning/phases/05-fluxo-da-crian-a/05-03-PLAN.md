Mission response fields used here:
- status: PENDING, AWAITING_APPROVAL, COMPLETED, REJECTED, CANCELLED.
- snapshotTitle, snapshotDescription, snapshotCoinValue, snapshotRequiresApproval, dueDate.

Backend behavior:
- GET /children/{childId}/missions returns PENDING missions only.
- POST /assigned-missions/{id}/complete returns the resulting assigned mission response.
- If snapshotRequiresApproval is false, backend may return COMPLETED and credit the wallet.
- If snapshotRequiresApproval is true, backend returns AWAITING_APPROVAL and does not credit coins.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mobile mission screen -> mission endpoints | Selected child id and assignedMissionId cross from mobile route/UI state to protected backend endpoints. |
| mission mutation response -> UI feedback | Backend status determines coin or approval feedback shown to the child. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Elevation of Privilege | ChildMissionsScreen/childService | mitigate | Use only token-authenticated childService calls; no familyUnitId field/path is accepted or sent. |
| T-05-02 | Elevation of Privilege / Information Disclosure | listPendingMissions/completeMission | mitigate | Backend family-scoped endpoints remain authority; mobile only passes selected child id and assignedMissionId from backend responses. |
| T-05-03 | Tampering | mission completion button | mitigate | Per-mission in-flight id blocks duplicate submits; backend INVALID_MISSION_STATUS remains final guard and is mapped to friendly copy. |
| T-05-05 | Information Disclosure | mission screens | mitigate | Do not display token, familyUnitId, accessPin, accessPinHash, raw enum names, HTTP details, or backend codes. |
| T-05-06 | Information Disclosure | mission error rendering | mitigate | Render UI-SPEC PT-BR messages or ApiError.userMessage only when user-safe; otherwise use `Não conseguimos atualizar essa missão. Tente novamente.` |
</threat_model>

# Phase 05 - UI Design Contract

> Visual and interaction contract for the Habitinhos child flow.
> Generated by `gsd-ui-phase` from the project roadmap, requirements, Phase 4
> mobile UI baseline, existing React Native tokens/components, and Phase 5
> design references.

## Scope

Phase 5 replaces the current child stub with the real child journey:

- `05-01`: child profile selection/access and home with balance.
- `05-02`: child missions list, detail, completion, and feedback.
- `05-03`: rewards catalog, redemption, success, and insufficient-balance
  states.

The child flow must consume backend data from the authenticated responsible
session. It must not create fake children, fake balances, fake missions, or
fake rewards when the backend is unavailable.

## Product Feel

The Phase 5 child flow must feel cheerful, motivating, simple, and safe. It may
be more playful than the responsible flow, but must still feel like a family
product rather than a game.

Visual hierarchy for Phase 5:

1. Child identity and current balance.
2. What the child can do now: pending missions or redeemable rewards.
3. Clear feedback for completion, waiting approval, success, or blocked action.
4. Secondary navigation: tabs, profile switching, retry, and logout.

Use emojis as lightweight icons. Use no more than one primary emoji per card,
and always pair emoji visuals with readable text.

## Spacing Scale

Declared values must stay centralized in `mobile/src/theme/spacing.ts` and be
used in React Native styles. All values are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tiny icon/text gaps and badge internals |
| sm | 8px | Compact vertical rhythm, inline gaps |
| md | 16px | Default component padding, list gaps, card content gaps |
| lg | 24px | Section gaps, header-to-content gaps, card clusters |
| xl | 32px | Major screen groups, hero balance separation |
| 2xl / xxl | 48px | Large first-screen vertical separation |
| 3xl / xxxl | 64px | Top visual breathing room only when content density allows |

Additional spacing constants:

| Token | Value | Usage |
|-------|-------|-------|
| screenHorizontal | 20px | Default horizontal screen padding on 360px-430px Android widths |
| cardPadding | 16px | Standard card body padding |
| bottomSafePadding | 24px | Extra bottom breathing room above safe area/tab bar |

Exceptions:

- `screenHorizontal: 20px` is allowed by the required mobile contract.
- Touch targets may use fixed `44x44` minimum.
- Primary buttons use `minHeight: 56`.
- Secondary buttons and compact controls use `minHeight: 48`.
- Progress bars use fixed `12px` height because the visual references require
  a slim pill track while preserving the 4px spacing scale. They must use
  `radius.full`.

Phase 5 layout rules:

- Screen sections use `spacing.lg` between major groups.
- Lists use `spacing.md` between cards.
- Cards never nest inside other cards unless the inner element is a simple
  non-shadowed soft panel.
- Bottom tab spacing must leave content readable and tappable above the safe
  area.

## Typography

Use only system fonts. Phase 5 must keep the existing four sizes and two
weights from Phase 4.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 24px |
| Label | 14px | 700 | 20px |
| Heading | 20px | 700 | 28px |
| Display | 28px | 700 | 36px |

Usage rules:

- Body text must not be smaller than 16px on primary child screens.
- Label text at 14px is allowed only for badges, helper text, tabs, coin
  metadata, and compact secondary details.
- Display is reserved for the child home greeting and prominent balance or
  detail titles. It must not be used inside compact cards.
- Use only weights `400` and `700`; map any Stitch `800` treatment to `700`.
- Long mission or reward names wrap to two lines inside cards; do not shrink
  below 16px to force a single line.

## Component Contracts

Phase 5 must compose from existing base components before adding new domain
components.

| Component | Phase 5 Contract |
|-----------|------------------|
| `AppScreen` | Safe area, background, `screenHorizontal` padding, scroll for home/list/detail/rewards, bottom safe padding |
| `AppHeader` | Child greeting/title, optional subtitle, `EmojiAvatar`, optional `CoinBadge`, simple right action |
| `Card` | Surface grouping with radius, padding, border, pressable state; use `highlight` only for selected/primary panels |
| `PrimaryButton` | 56px high; one primary action per screen or focused card cluster |
| `SecondaryButton` | 48px high; back, details, profile switch, retry, and logout |
| `CoinBadge` | Balance, mission reward, and reward cost; add `variant` only if needed without changing token roles |
| `StatusBadge` | Map child statuses to text and semantic colors; extend variants if needed while preserving token roles |
| `EmojiAvatar` | Profile identity without photos or external images; map backend `avatarKey` to an emoji fallback |

New domain components required by Phase 5:

| Component | Contract |
|-----------|----------|
| `BottomTabBar` | Four destinations: `Início`, `Missões`, `Recompensas`, `Perfil`; emojis or simple text+emoji only; active state uses text, pill shape, and `tabActive`/`primarySoft`; minimum item target `44x44`; no external icons |
| `ProgressBar` | Pill track using `surfaceMuted`; fill uses `primary`, `success`, or `accent`; value clamped 0-100; must expose accessible text like `3 de 5 missões concluídas` |
| `MissionCard` | Emoji/avatar, mission title, optional description, `CoinBadge`, `StatusBadge`, and one action or pressable detail affordance; states: `pending`, `awaiting_approval`, `completed`, `rejected`, `cancelled` |
| `RewardCard` | Emoji/avatar, reward title, optional description, cost `CoinBadge`, availability message, redeem action or disabled/progress panel; states: `available`, `insufficient_balance`, `redeemed`, `unavailable` |
| `EmptyState` | Emoji, title, helper text, optional action; no card nesting; can be a soft panel or unframed section |
| `FeedbackBanner` | Success/warning/error inline banner for completion, waiting approval, redemption success, insufficient balance, and recoverable API errors |

Component-specific rules:

- `MissionCard` pending cards may show `Concluir missão` only when completion is
  possible from that card. Otherwise card press opens the detail screen.
- Completed cards use `success` border/badge and do not show a completion CTA.
- Awaiting approval cards use `warningSoft`/`accentDark` and copy
  `Aguardando aprovação`.
- Rejected cards use `errorSoft`/`error` and must show the responsible's reason
  only when available and friendly.
- Reward cards with insufficient balance keep the redeem action visible but
  disabled and explain the exact missing amount.
- All pressables have `accessibilityLabel` with the action and object name.

## API Data Contract For UI States

The UI must represent the existing backend shape honestly.

| Backend Data | UI Use |
|--------------|--------|
| `GET /children` -> `ChildResponse[]` | Profile selection list; show only active children |
| `GET /children/{childId}/wallet` -> `WalletResponse.balance` | Home balance, header badge, rewards affordability |
| `GET /children/{childId}/missions` -> pending `AssignedMissionResponse[]` | Child mission list and home pending summary |
| `POST /assigned-missions/{id}/complete` | Mission completion action and feedback |
| `GET /rewards` -> `RewardResponse[]` | Rewards catalog |
| `POST /rewards/{id}/redeem` with `{ childId }` | Redemption action and success/insufficient-balance feedback |

Status mapping:

| Backend Status | UI Label | Visual State |
|----------------|----------|--------------|
| `PENDING` | `Pendente` | neutral/selected pending card with completion action |
| `AWAITING_APPROVAL` | `Aguardando aprovação` | warning badge/panel; no repeat completion action |
| `COMPLETED` | `Concluída` | success badge/border; show coin impact |
| `REJECTED` | `Revisar com responsável` | error/warning badge; show `Motivo: {reason}` when available |
| `CANCELLED` | `Indisponível` | muted/locked card; no primary action |

Data refresh rules:

- After mission completion, refresh wallet and mission list. If backend returns
  `COMPLETED`, show earned coins immediately. If it returns
  `AWAITING_APPROVAL`, show waiting approval copy and do not change balance
  unless the wallet refresh confirms a new balance.
- After reward redemption success, refresh wallet and rewards. Show the new
  balance from backend, not a client-only subtraction.
- While refreshing, preserve layout dimensions and prevent duplicate submits.
- The current child mission list endpoint returns pending missions only. Do not
  display completed/total daily progress unless the implementation adds or
  consumes a real API shape that provides those counts. With the current API,
  use pending count summaries and immediate completion feedback.

### ChildHome

Purpose: show the selected child their current coins and the next useful action.

Visual contract:

- Use a friendly `AppHeader` with child avatar and greeting:
  `Oi, {childName}!`
- Show balance in a prominent `Card`/highlight panel before mission lists.
- Balance copy: `Seu tesouro` and `{balance} moedas`.
- Show a pending mission summary from real data:
  `Você tem {pendingCount} missão pendente hoje.` When real completed/total
  counts are available, a progress card may use
  `{completedCount} de {totalCount} missões concluídas`.
- Show up to three pending missions as cards/rows and a primary route action
  `Ver missões`. Awaiting-approval rows may appear only from immediate
  completion feedback or a future real API response.
- Show a reward prompt only when rewards are loaded. If a reward is affordable,
  use `Você pode resgatar: {rewardTitle}`. If not, use
  `Falta pouco para resgatar: {rewardTitle}` with missing coins.

Required states:

| State | Required UI |

| No missions | `Nenhuma missão hoje` + `Quando houver uma nova missão, ela aparece aqui.` |
| No rewards | Omit reward prompt or show low-emphasis `As recompensas aparecem quando a família criar uma.` |
| Error | Friendly error panel plus `Tentar novamente`; keep tab/navigation visible |

Required copy:

| Element | Copy |
|---------|------|
| Greeting | `Oi, {childName}!` |
| Encouragement | `Você está indo muito bem!` |
| Balance label | `Seu tesouro` |
| Balance value | `{balance} moedas` |
| Progress title | `Missões de hoje` |
| Pending summary | `Você tem {pendingCount} missão pendente hoje.` |
| Progress value | `{completedCount} de {totalCount} concluídas` only when real counts exist |

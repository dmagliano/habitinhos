Existing mobile API wrapper:
- apiRequest<T>(path: string, options?: { method?: 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE'; body?: unknown; token?: string | null; headers?: Record<string, string> }): Promise<T>
- ApiError exposes status, code, details, userMessage, isNetworkError, and isSessionExpired.
- apiRequest rejects any client body/path containing familyUnitId.

Existing auth context:
- useAuth() returns { status, session, errorMessage, login, logout, retryRestore }.
- session.token is the responsible JWT; selected child is route/UI state, not a new authenticated principal.

DTO contracts to add in mobile/src/api/types.ts:
- ChildResponse: id, name, age, avatarKey, active, createdAt, updatedAt.
- WalletResponse: childId, balance, createdAt, updatedAt.
- AssignedMissionStatus: PENDING, AWAITING_APPROVAL, COMPLETED, REJECTED, CANCELLED.
- AssignedMissionResponse: id, missionId, childId, status, dueDate, completedAt, approvedAt, rejectedAt, rejectionReason, snapshotTitle, snapshotDescription, snapshotCoinValue, snapshotRequiresApproval, createdAt, updatedAt.
- RewardResponse: id, title, description, cost, active, createdAt, updatedAt.
- RewardRedemptionStatus: REDEEMED.
- RewardRedemptionResponse: id, rewardId, childId, walletId, status, snapshotTitle, snapshotCost, coinTransactionId, createdAt, updatedAt.

Backend route reality:
- GET /children
- GET /children/{childId}/wallet
- GET /children/{childId}/missions returns pending missions only.
- POST /assigned-missions/{id}/complete
- GET /rewards
- POST /rewards/{id}/redeem with body { childId }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mobile child UI -> Spring API | Responsible JWT crosses from mobile into protected backend endpoints; selected child id is untrusted input. |
| selected child route params -> child service | Route params can be manipulated by a client; backend must remain source of authorization truth. |
| package install -> mobile runtime | New npm dependency enters Expo mobile runtime. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Elevation of Privilege | childService/apiRequest | mitigate | `childService` never accepts familyUnitId; `apiRequest` existing guard rejects familyUnitId in path/body; child-service test asserts route payloads. |
| T-05-02 | Elevation of Privilege / Information Disclosure | ChildProfileSelect/ChildHome | mitigate | Profile selection comes only from GET /children under responsible JWT; all wallet/mission/reward reads use selected child id and backend family-scoped lookups. |
| T-05-05 | Information Disclosure | ChildProfileScreen/AuthContext | mitigate | Keep responsible JWT inside AuthContext/SecureStore; do not render token, familyUnitId, accessPin, or accessPinHash in any child screen. |
| T-05-06 | Information Disclosure | EmptyState/FeedbackBanner/API error rendering | mitigate | Render `ApiError.userMessage` or UI-SPEC copy; do not show backend code, HTTP details, stack traces, or enum names as visible copy. |
| T-05-SC | Tampering | npm install for @react-navigation/bottom-tabs | mitigate | Use `cd mobile && npx expo install @react-navigation/bottom-tabs`; Package Legitimacy Audit in 05-RESEARCH marks the package Approved with slopcheck OK and no [ASSUMED]/[SUS] package. |
</threat_model>

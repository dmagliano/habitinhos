# Phase 07 — UI Design Contract

> Visual and interaction contract for Phase 7 registration polish. Generated by `gsd-ui-phase`, verified inline against the six UI dimensions.

---

## Design Intent

Make the registration screen feel demo-ready, clear, and trustworthy without turning the auth flow into a new design project. The screen should keep the existing quiet card form, PT-BR tone, shared tokens, and familiar auth structure while making password requirements and disabled-submit behavior understandable.

This contract is intentionally narrow: it covers `AuthRegister` polish only. Broader Phase 7 visual consistency checks still use `docs/design/mobile-design-contract.md` and `docs/design/phase-design-map.md`.

Registration-specific spacing contract:

- Keep `styles.form.gap = spacing.md`.
- Keep each field using `gap: spacing.xs`.
- Place `Confirmar senha` immediately after `Senha` with the same field structure and gap.
- Place the disabled-button explanation immediately before `Criar conta`, after backend/inline errors if present. Use existing body/helper text rhythm; do not create a new card, banner, checklist, or alert block.

## Interaction Contract

### Field Order

The registration form order must be:

1. `Nome`
2. `E-mail`
3. `Senha`
4. `Confirmar senha`
5. `Nome da família`
6. `PIN do responsável`
7. Registration-specific error or inline validation messages
8. Disabled-submit explanation, when disabled
9. `Criar conta`
10. `Já tenho conta`

### Local Validity

`Criar conta` is enabled only when all conditions are true:

- `name.trim()` is not empty.
- `email.trim()` is not empty.
- `password.length >= 8`.
- `confirmPassword` equals `password`.
- `familyName.trim()` is not empty.
- `responsiblePin` has exactly 4 digits.
- The screen is not loading.

When any condition is false and the screen is not loading:

- Keep `Criar conta` disabled.
- Show `Complete os campos obrigatórios para criar a conta.` near the button.

When loading:

- Keep the button disabled through `loading`.
- Show `Criando conta...` via the existing `PrimaryButton` loading state.
- Do not show duplicate loading text elsewhere.

### Submit Behavior

- `handleSubmit` must guard against invalid local form state and loading before calling `register`.
- `Confirmar senha` is mobile-only and must not be sent to the backend.
- The backend request body remains `{ name, email, password, familyName, responsiblePin }`.

## Accessibility Contract

- `Confirmar senha` input must have `accessibilityLabel="Confirmar senha"`.
- Existing labels must remain queryable by visible text/accessibility label:
  - `Nome`
  - `E-mail`
  - `Senha`
  - `Nome da família`
  - `PIN do responsável`
  - `Criar conta`
  - `Já tenho conta`
- The disabled explanation and mismatch message must be visible `Text`, not only placeholder, style change, console output, or test-only metadata.
- Touch targets remain controlled by existing buttons: primary minimum height 56px, secondary minimum height 48px.
- The additional field must remain usable with the keyboard on Android and iOS through the existing `KeyboardAvoidingView`.

## State Contract

| State | Required Behavior |
|-------|-------------------|
| Empty/default | `Criar conta` disabled; generic disabled explanation visible near the button |
| Partial required fields | `Criar conta` disabled; generic disabled explanation visible |
| Password shorter than 8 | `Criar conta` disabled; password placeholder communicates minimum before typing |
| Confirmation empty | No mismatch error yet; `Criar conta` disabled |
| Confirmation differs | Show `As senhas precisam ser iguais.` inline; `Criar conta` disabled |
| Valid form | Hide generic disabled explanation; enable `Criar conta` |
| Loading | Show `Criando conta...`; prevent duplicate submits |
| Backend/API error | Preserve existing registration-specific error display; do not show stale-session copy |

## Test Contract

Focused mobile tests should prove:

- `Confirmar senha` renders directly after `Senha` and before `Nome da família`.
- `Senha` uses placeholder `Mínimo de 8 caracteres`.
- `Criar conta` starts disabled and shows `Complete os campos obrigatórios para criar a conta.`.
- `As senhas precisam ser iguais.` appears only after a non-empty mismatching confirmation.
- `register` is not called while the form is invalid.
- `register` is called with the unchanged backend payload after all fields are valid.
- Existing stale-session filtering on registration still passes.

Use existing `mobile/src/features/auth/__tests__/login-screen.test.tsx` patterns unless the planner creates a more focused register test file.

# Phase 06.3-01 Summary: Backend reset/delete endpoints

## Completed

- Added reset-token persistence with purpose-scoped, hashed, expiring, single-use tokens in `auth_reset_tokens`.
- Added backend DTOs and endpoints for:
  - `POST /auth/password-reset/request`
  - `POST /auth/password-reset/confirm`
  - `POST /auth/responsible-pin/reset/request`
  - `POST /auth/responsible-pin/reset/confirm`
  - `DELETE /me`
- Wired `AuthService` to issue/reset tokens, update password/PIN hashes, deactivate accounts, and reject inactive users on authenticated requests.
- Reused `AccountEmailSender` for welcome, password reset, and responsible PIN reset messages.
- Updated security rules so only password-reset request/confirm are public.
- Updated Bruno OpenAPI contract and OpenAPI smoke coverage for the new auth endpoints.

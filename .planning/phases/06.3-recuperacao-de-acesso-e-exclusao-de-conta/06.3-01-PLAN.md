<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public reset request -> user lookup | Caller can submit arbitrary emails. |
| Email token -> credential update | Anyone with token/code can attempt password/PIN update. |
| Authenticated user -> destructive account action | Active JWT holder requests account deletion. |
| Email provider -> application | Provider delivers raw reset code/token. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06.3-01-01 | Information Disclosure | Password reset request | mitigate | Enumeration-safe response for missing/existing emails. |
| T-06.3-01-02 | Tampering | Reset token storage | mitigate | Store only hashes, validate purpose/expiration/used state transactionally. |
| T-06.3-01-03 | Spoofing | PIN reset request | mitigate | Require authenticated responsible session and current account password before issuing token. |
| T-06.3-01-04 | Elevation of Privilege | Token confirmation | mitigate | Purpose-scoped tokens; password token cannot reset PIN and vice versa. |
| T-06.3-01-05 | Denial of Service | Reset request spam | accepted | MVP does not implement rate limiting; note for future production hardening. |
| T-06.3-01-06 | Repudiation | Account deletion | mitigate | Log deactivation event with user/family ids; preserve records. |
</threat_model>

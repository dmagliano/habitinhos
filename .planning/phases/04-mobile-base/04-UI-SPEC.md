# Phase 04 - UI Design Contract

> Visual and interaction contract for the Habitinhos Expo mobile foundation.
> Generated by `gsd-ui-phase`, verified against the 6 UI quality dimensions.

## Scope

Phase 4 establishes the visual foundation for the React Native + Expo app:
tokens, base components, login/access screen, authenticated `FamilyHub`, and
the honest responsible/child stub screens.

This phase must not build the full child mission/reward flow, full responsible
dashboard/management flow, real bottom-tab destinations, demo seed data, or any
fake domain data that looks functional.

Primary visual references:

- `docs/design/stitch/boas_vindas/screen.png`
- `docs/design/stitch/perfil_e_troca_de_modo/screen.png`

Reference screenshots guide hierarchy, rhythm, tone, and component shape only.
Do not copy Stitch `code.html`, HTML, CSS, Tailwind classes, DOM structure, or
web-only interaction patterns.

## Product Feel

The Phase 4 UI should feel familiar, light, playful, organized, and trustworthy.
Use a calm family-app tone, not a dense admin panel and not a toy-like game.

Visual hierarchy for Phase 4:

1. Brand/product promise or authenticated screen title.
2. Primary action for the current screen.
3. Supporting copy, secondary actions, and mode-switch actions.
4. Technical recovery actions such as retry or logout.

## Spacing Scale

Declared values must be centralized as tokens and used in React Native styles.
All values are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tiny icon/text gaps and badge internals |
| sm | 8px | Compact vertical rhythm, inline gaps |
| md | 16px | Default component padding and field gaps |
| lg | 24px | Section gaps and card clusters |
| xl | 32px | Major screen groups and welcome spacing |
| 2xl | 48px | Large first-screen vertical separation |
| 3xl | 64px | Top visual breathing room when available |

Additional spacing constants:

| Token | Value | Usage |
|-------|-------|-------|
| screenHorizontal | 20px | Default horizontal screen padding on 360px-430px Android widths |
| cardPadding | 16px | Standard card body padding |
| bottomSafePadding | 24px | Extra bottom breathing room when no real tab bar is present |

Exceptions:

- `screenHorizontal: 20px` is allowed because the Habitinhos mobile contract
  defines it as the Android-first screen padding target.
- Touch targets may use fixed `44x44` minimum and primary buttons may use fixed
  `56px` height. Both preserve the 4px grid.

## Typography

Use only system fonts. Keep the implementation type scale constrained to four
sizes and two weights during Phase 4.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 24px |
| Label | 14px | 700 | 20px |
| Heading | 20px | 700 | 28px |
| Display | 28px | 700 | 36px |

Usage rules:

- Body text must not be smaller than 16px on primary screens.
- Label text at 14px is allowed only for badges, helper text, and compact
  metadata.
- Display is reserved for the welcome/access headline.
- Avoid adding new sizes or weights in Phase 4; map Stitch `800` headings to
  the single strong weight `700` for implementation consistency.

general interactive accent.

Accent must not be used for every pressable element. Secondary and neutral
actions should use soft surfaces and text color hierarchy.

## Radius And Shadows

| Token | Value | Usage |
|-------|-------|-------|
| radiusSm | 8px | Small badges or compact controls |
| radiusMd | 12px | Inputs and compact cards |
| radiusLg | 16px | Standard cards and buttons |
| radiusXl | 24px | Highlight cards and profile/mode cards |
| radiusFull | 999px | Pills, badges, avatar circles |

Shadow/elevation:

- Standard card: Android `elevation: 2`, soft shadow values from
  `docs/design/stitch/DESIGN.md`.
- Floating emphasis: Android `elevation: 4` only for prominent cards or
  anchored action areas.
- Do not use heavy, dark, or realistic shadows.

## Screen Contracts

### Auth / Login

Purpose: let the responsible adult access the real backend account.

Visual contract:

- Use the calm welcome tone from `boas_vindas`.
- Top area may use simple emoji cards or brand mark treatment, but no image
  assets and no copied HTML/CSS.
- Primary focal point is the login/access action and form.
- Form fields use `surface`, `border`, 16px text, and 48px minimum height.
- Loading state disables the submit button and preserves layout height.

Required copy:

| Element | Copy |
|---------|------|
| Brand label | `Habitinhos` |
| Headline | `Transforme tarefas em pequenas conquistas` |
| Supporting copy | `Entre para acompanhar missões, moedas e recompensas da família.` |
| Email label | `E-mail` |
| Password label | `Senha` |
| Primary CTA | `Entrar na conta` |
| Loading CTA | `Entrando...` |
| Retry CTA | `Tentar novamente` |

### Session Restore / Loading

Purpose: prevent a flash of incorrect navigation while token restoration and
`/me` verification are in progress.

Visual contract:

- Use `AppScreen` with centered brand label and native activity indicator or
  simple rounded skeleton blocks.
- Keep copy short: `Preparando sua família...`
- Do not show fake children, missions, rewards, or balances.

### FamilyHub

Purpose: first authenticated landing after login/session restore.

Visual contract:

- Use `AppHeader` with family-aware title/subtitle when backend context is
  available.
- Show two equally prominent `Card`/button choices:
  `Sou responsável` and `Sou criança`.
- Choice cards may use emojis and soft backgrounds to indicate role, but must
  include text labels.
- Include visible logout affordance in header/menu.

Required copy:

| Element | Copy |
|---------|------|
| Title | `Escolha como quer entrar` |
| Subtitle | `Você está na família {familyName}.` |
| Responsible choice | `Sou responsável` |
| Child choice | `Sou criança` |
| Logout | `Sair da conta` |

### ResponsibleStub

Purpose: authenticated placeholder for the responsible flow without fake
management features.

Visual contract:

- Use `AppHeader`, `Card`, `StatusBadge`, and `SecondaryButton`.
- Keep tone calmer and more organized than the child stub.
- Do not show dashboard numbers, approval counts, child lists, or fake actions.

Required copy:

| Element | Copy |
|---------|------|
| Title | `Área do responsável` |
| Status | `Em preparação` |
| Body | `Em breve você vai acompanhar missões, crianças e recompensas por aqui.` |
| Switch mode | `Trocar modo` |
| Logout | `Sair da conta` |

### ChildStub

Purpose: authenticated placeholder for the child flow without fake mission or
reward data.

Visual contract:

- Use a slightly more playful emoji/avatar treatment than responsible stub.
- Do not show fake balances, fake missions, fake rewards, or completion CTAs.
- Show `Trocar modo` and visible logout.

Required copy:

| Element | Copy |
|---------|------|
| Title | `Área da criança` |
| Status | `Quase pronto` |
| Body | `Logo as missões e recompensas da família aparecem aqui.` |
| Switch mode | `Trocar modo` |
| Logout | `Sair da conta` |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Entrar na conta` |
| Secondary CTA | `Trocar modo` |
| Retry CTA | `Tentar novamente` |
| Empty state heading | `Nada para mostrar ainda` |
| Empty state body | `Quando essa área estiver pronta, as informações da família aparecem aqui.` |
| Auth error state | `Não conseguimos entrar agora. Revise os dados e tente novamente.` |
| Network error state | `Não conseguimos conectar ao servidor. Verifique a conexão e tente novamente.` |
| Session expired state | `Sua sessão terminou. Entre novamente para continuar.` |
| Destructive confirmation | Not applicable - Phase 4 has no destructive data mutation; logout is session-only and must be labeled `Sair da conta`. |

Copy rules:

- Visible UI text is PT-BR.
- Code identifiers, route names, component names, and test names stay in
  English.
- Do not show raw backend `code`, exception names, stack traces, or technical
  HTTP details in the UI.
- Backend PT-BR validation messages may be shown when they are friendly and
  specific; otherwise map to the copy above.

## State Contract

| State | Required UI |
|-------|-------------|
| Default | Stable layout, clear primary action, no layout jump |
| Pressed | Visible pressed feedback through opacity or subtle fill change |
| Disabled | Lower emphasis and block repeated submits during loading |
| Loading | Native indicator or rounded skeleton; preserve button/screen dimensions |
| Error | Friendly PT-BR message plus `Tentar novamente` when recoverable |
| Selected | Role/mode card uses text plus color/border, never color alone |
| Authenticated | Show `FamilyHub` before any role stub |
| Logged out | Clear session and return to auth branch |

## Accessibility Contract

- Primary buttons are 56px high.
- Secondary buttons and inputs are at least 48px high.
- All pressable targets are at least 44x44.
- Emoji-only visuals must have adjacent text and accessibility labels.
- Important status combines text, color, and badge/shape.
- Form fields have clear labels and error text linked visually below the field.
- Layout must remain usable at Android widths from 360px to 430px.

## Registry Safety

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| none | none | not applicable - custom React Native components only |

No shadcn, third-party registry, external visual asset, Lottie, complex SVG,
external image, profile photo, or mandatory external font is allowed in Phase 4.

## Implementation Guardrails

- Implement native React Native components with `View`, `Text`, `Pressable`,
  `ScrollView`, `FlatList` when needed, and `SafeAreaView`.
- Centralize tokens before building screens.
- Compose screens from required base components instead of one-off styles.
- Do not import from `docs/design/stitch/*/code.html`.
- Do not create web/Tailwind/DOM abstractions in the mobile app.
- Do not use mock/offline fallback for backend availability.
- Do not show `familyUnitId` as an authorization input or client-side truth.

# Phase 06.2 UI Spec

## Design Intent

Reduce friction in the demo path. The app should feel like it has one obvious default path: login/register, choose a child, play. Family management remains accessible, but it should be a direct action from the places where the responsible naturally needs it.

## Screen Requirements

### Register

- Do not show expired-session or login-recovery copy on this screen.
- Keep the current card form structure, fields, `Criar conta`, and `Já tenho conta`.
- Registration-specific validation/API errors may still appear below the form fields.

### Children Management

- Use `Cadastrar criança` for the primary child creation action.
- Avoid mixed copy where the same action is sometimes `Nova criança` and sometimes `Cadastrar criança`.
- The form title may remain `Nova criança` only if it describes the draft entity rather than the action; executor may improve it to `Cadastrar criança` if tests and layout remain stable.

### Child Selector

- Primary task remains selecting a child and pressing `Entrar no perfil`.
- Add a secondary action `Gerenciar família` on the selector itself.
- Remove or replace `Voltar para família`; the selector should not route users back to entry-mode selection.
- `Gerenciar família` opens responsible management directly.

### Responsible Home

- Add a visible action `Retornar às crianças` near the top of the screen, before dense dashboard content.
- It should navigate to the standard child selector (`Quem vai brincar agora?`).
- Keep existing dashboard metrics, children, actions, approvals, and recent redemptions unchanged.

## Accessibility

- New actions must be discoverable through `getByRole('button', { name })` in tests.
- Button labels must match visible text exactly:
  - `Cadastrar criança`
  - `Gerenciar família`
  - `Retornar às crianças`

## Non-Goals

- No new role-selection screen.
- No backend auth/session change.
- No new modal or onboarding layer.
- No visual redesign beyond copy/action placement.

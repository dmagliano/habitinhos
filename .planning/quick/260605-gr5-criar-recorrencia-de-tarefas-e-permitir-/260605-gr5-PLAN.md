# Quick Plan: Recorrencia e Reprovar Para Refazer

## Objetivo

Adicionar recorrencia simples de missoes (`ONCE`, `DAILY`, `WEEKLY`) e permitir
que o responsavel reprove uma missao enviada com opcao padrao de devolve-la
como pendente para a crianca refazer, exibindo a justificativa no fluxo da
crianca.

## Decisoes Travadas

- A UI mostra apenas `ONCE`, `DAILY` e `WEEKLY`; `CUSTOM` fica fora do MVP.
- Recorrencia nao usa scheduler: a proxima ocorrencia nasce apos credito
  automatico ou aprovacao.
- Reprovar com `Devolver para refazer` vem marcado por padrao.
- A mensagem de reprova aparece para a crianca enquanto a missao estiver
  pendente para refazer e some quando ela reenviar.

## Escopo

- Backend:
  - Estender o contrato de reprova com `returnToPending`.
  - Permitir devolver uma missao `AWAITING_APPROVAL` para `PENDING` sem
    creditar moedas.
  - Limpar estado de reprova quando a crianca reenviar.
  - Criar a proxima ocorrencia para missoes `DAILY` e `WEEKLY` apos credito.
  - Evitar duplicar ocorrencias abertas para a mesma crianca/missao.
- Mobile responsavel:
  - Expor selecao simples de recorrencia na criacao/edicao de missoes.
  - Adicionar controle `Devolver para refazer` no modal de reprova, marcado por
    padrao.
- Mobile crianca:
  - Mostrar a justificativa da reprova em cards/detalhes de missoes pendentes
    devolvidas para refazer.

## Tarefas

1. Backend RED/GREEN
   - Atualizar testes de aprovacao/reprova para cobrir:
     - reprova com `returnToPending=true` retorna `PENDING`, preserva
       `rejectionReason`, nao credita moedas e aparece em
       `GET /children/{childId}/missions`;
     - reenviar a missao limpa a mensagem e volta ao fluxo normal;
     - reprova com `returnToPending=false` permanece `REJECTED`;
     - aprovar ou completar missao recorrente cria a proxima ocorrencia
       `PENDING` com `dueDate` avancado.
   - Implementar `returnToPending` em `RejectAssignedMissionRequest`,
     `AssignedMission` e `AssignedMissionService`.
   - Adicionar snapshot de recorrencia em `AssignedMission` se necessario, com
     migration Flyway e DTO atualizado.

2. Mobile RED/GREEN
   - Atualizar tipos em `mobile/src/api/types.ts` para `returnToPending` e
     eventual snapshot de recorrencia.
   - Atualizar testes de `responsible-approvals` para o toggle marcado por
     padrao e payload `{ reason, returnToPending: true }`.
   - Atualizar testes de missoes da crianca para exibir mensagem de reprova em
     card/detalhe e permitir concluir novamente.
   - Implementar UI de recorrencia em `ResponsibleMissionFormScreen`.
   - Implementar toggle de reprova em `ResponsibleApprovalsScreen`.
   - Implementar copia de reprova em `MissionCard` e
     `ChildMissionDetailScreen`.

3. Verificacao e documentacao leve
   - Atualizar `docs/api-contract.md` ou README/API notes se o contrato de
     reprova mudar de forma visivel.
   - Rodar testes focados:
     - `cd backend && ./mvnw test -Dtest=MissionApprovalIntegrationTest,MissionAssignmentIntegrationTest`
     - `cd mobile && npm test -- responsible-approvals child-missions`
     - `cd mobile && npm run typecheck`
   - Rodar suites mais amplas se os focados passarem:
     - `cd backend && ./mvnw test`
     - `cd mobile && npm test`
